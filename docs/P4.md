# P4：可观测性与交付

P1–P3 解决了"能跑、能扩、能恢复"，P4 解决"出事时能查、交付时能验"。

## 一、trace_id 全链路

`app/observability.py` 用 `contextvars` 保存 trace_id：

- 入口取 `X-Request-ID`，没有就生成 16 位；
- 响应头回写 `X-Request-ID`，方便前端/网关对账；
- 日志格式统一为 `时间 级别 [trace_id] 模块: 消息`；
- 后台 `asyncio.create_task` 会**复制**当前上下文，所以一次请求触发的任务执行
  自动带同一个 trace，不需要层层传参。

```
2026-11-04 16:16:20,194 INFO    [91cfc382fb794e02] app.api.routes: task 378c... queued (session=s1, len=2)
```

> 注意：跨进程（ARQ worker）不会自动传递 contextvar。worker 侧需要从任务参数
> 或 Redis 里取出 trace_id 再 `set_trace_id()`——这是下一步要补的。

## 二、Prometheus 指标

`app/metrics.py` 定义了 5 个指标，`/metrics` 端点暴露（不需要鉴权，方便抓取）：

| 指标 | 类型 | 说明 |
|---|---|---|
| `cmekg_http_requests_total{method,path,status}` | Counter | HTTP 请求量与状态码分布 |
| `cmekg_http_request_duration_seconds{method,path}` | Histogram | HTTP 耗时 |
| `cmekg_turns_total{status}` | Counter | 单轮对话终态分布 |
| `cmekg_turn_duration_seconds{status}` | Histogram | 单轮对话耗时（从 RUNNING 到终态） |
| `cmekg_turn_retries_total` | Counter | 因瞬时错误重试的次数 |

**标签基数是刻意控制的**：`path` 用路由模板（`/api/v1/tasks/{task_id}`）而不是
真实 URL，否则每个 task_id 都会变成一个独立时间序列，把 Prometheus 打爆。

`cmekg_turn_duration_seconds` 的耗时取自任务记录里的 `started_at/finished_at`，
而不是在函数里手动计时——这样即便重启后由别的进程收敛，数据依然正确。

## 三、CI

`.github/workflows/ci.yml`：`ruff check` → `mypy app` → `pytest --cov --cov-fail-under=60`。

几个必要的环境细节：

- 先装 `libportaudio2` / `libsndfile1`，否则 `import sounddevice` 失败；
- 注入 dummy `OPENAI_API_KEY`，只为让 `ChatOpenAI` 在 import 期能构造（不会发请求）；
- `pytest` 的 `addopts` 里排除了 4 个历史脚本式测试（它们会真的调 LLM/讯飞），
  保证 CI 离线可跑。

### 类型检查的范围取舍

`Graph/`、`Chains/` 是未类型化的既有 Agent 层（大量 LangChain 泛型 + 没有注解），
`pyproject.toml` 里对它们设 `ignore_errors = true`，**CI 只对新增平台层 `app/` 做严格检查**。
这是刻意的：把"没有注解"当成"类型错误"只会让 CI 永远红着，反而失去意义。


覆盖率最高的模块：`config` / `metrics` / `observability` / `security` / `schemas` 均接近 100%；

## 五、遗留

- 没有接入 OpenTelemetry 导出（当前 trace 只在本进程日志里，跨服务需要 OTel）；
- 没有告警规则（Prometheus 侧配置，属于部署范畴）；
- 指标里没有记录 LLM token 用量（需要从回调里取）。

> trace 跨进程已补齐：创建任务时把 `trace_id` 写进任务记录（内存/Redis 都存），
> worker 取到任务后 `set_trace_id()`，于是 API 进程与 worker 进程的日志是同一个
> trace_id。见 `tests/test_lease_and_trace.py::test_runner_restores_trace_id_from_task_record`。
